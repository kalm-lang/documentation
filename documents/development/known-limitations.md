# Supported semantics and remaining v1 work

**Implemented and exercised:** Java 25 source generation for functions, classes, contracts, records, enums, singletons, aliases, annotations, externals, augment helpers, bindings, loops, `choose`, exceptions, `with`, `defer`, `guard`, `expect`/`require`/`ensure`, safe access, `??`, virtual-thread tasks and `await`; CLI check/compile/run/test/build; Maven main and test generation with a test runner; an independent demo and VS Code highlighting/snippets.

**Not fully conformant to the v1.0 draft:**

- The source-level checker covers only selected local/fixed and explicitly known nullable-receiver rules, not full Kalm type/name/flow analysis. Basic syntax and semantic errors have codes, and the CLI supports `--diagnostic-format json`; complete per-error code classification is not yet present. CLI and build-plugin javac precheck diagnostics map to the nearest Kalm declaration/statement span, not an exact expression-level source range. Downstream Java compiler errors may still report generated Java positions when prechecking cannot resolve a generated type. Java library name resolution is delegated to `javac`.
- Constructor-vs-function calls and augment/index rewriting use the declaration index plus simple capitalization and syntactic receiver types, not full overload or generic resolution. Imported Java types and generic augment target types still need full symbol resolution in edge cases.
- Type and import aliases resolve within their file/package; duplicate same-named Kalm types across packages still need full symbol-resolution coverage in edge cases. Generic `choice` declarations are rejected because this backend uses Java enums. `forward` handles compiled Java interfaces with basic generic substitution and checked throws, but complex inherited generic bindings need broader conformance coverage; `external fun` needs a uniquely identifiable compiled Java overload to preserve checked throws. Accessors and guarded lazy/late field reads require a syntactically known receiver type; constructor checking covers ordinary branches but not all exceptional/control-flow paths. Complete closed-hierarchy validation and Java interop edge cases remain unfinished.
- Async `await` blocks a virtual thread, rather than generating continuations. The emitter rejects `await` outside an async function or task and within a guard; full async control-flow and error-boundary analysis are still missing. Java's type system catches some invalid programs only after generation.
- The optional compiler-backed language server covers syntax, selected semantic rules and open-document editor operations, but not Java-aware completion/refactoring or workspace-wide symbol resolution. The VS Code extension retains a lightweight local analyzer unless `kalm.languageServer.command` is configured. The IntelliJ plugin requires LSP4IJ and an externally installed `kalm-lsp`; Maven/Gradle Kalm root/dependency import and independent platform editor fixtures remain incomplete. The Gradle plugin handles Java source sets and Kalm test XML but has no HTML report or published plugin-portal artifact yet. Full JPMS application builds (although CLI dependencies can be placed on `--module-path`), full Java source-set analysis and cross-platform distribution packaging are not implemented.

The compiler requires JDK 25 or newer; the runtime is a separate ordinary dependency. Use `mvn clean verify` after deleting sources when stale class files need removal.
